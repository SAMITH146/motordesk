3.1 Requerimientos Funcionales (Implementados / Parciales)

Id. Del requisito RF01
Nombre del requisito Registrar clientes
Componente Un módulo de gestión de clientes
Característica asociada Almacenamiento seguro, accesibilidad
Descripción del requisito El sistema debe permitir registrar clientes
con datos personales como nombre,
cédula, teléfono y correo electrónico.
Características Validación de campos obligatorios y
formatos, consulta rápida del cliente
por documento o nombre.
Prioridad Alta
Restricciones Sólo el administrador y mecánicos
autorizados pueden registrar clientes.
Interacción humano-tecnológica Si
Interacción tecnológica- tecnológica Si
Estado de implementación: SI (Completado)
Detalles de implementación: Se guardan de manera automática en la base de datos al crearse una orden de trabajo por el mecánico. El administrador tiene la capacidad de listarlos y editarlos.

--------------------------------------------------------------------------------

Id. Del requisito RF02
Nombre del requisito Gestionar vehículos
Componente Un módulo de gestión de vehículos
Característica asociada Registro dinámico, actualización en tiempo real
Descripción del requisito Permitir el registro y actualización de
vehículos por cliente: marca, modelo,
placa, tipo y año.
Características Validación de placas duplicadas y
vínculo directo al dueño.
Prioridad Alta
Restricciones Cada vehículo debe pertenecer a un
cliente registrado.
Interacción humano-tecnológica Si
Interacción tecnológica- tecnológica Si
Estado de implementación: SI (Implícito)
Detalles de implementación: Se asocian dinámicamente al cliente y al ID de la orden de servicio al momento de la creación de la misma. Las placas repetidas se rechazan por restricción UNIQUE de la base de datos.

--------------------------------------------------------------------------------

Id. Del requisito RF03
Nombre del requisito Crear y gestionar órdenes de servicio
Componente Módulo de órdenes de trabajo
Característica asociada Automatización, control de proceso
Descripción del requisito Crear órdenes asociadas a vehículos
indicando servicio solicitado, estado y
descripción técnica.
Características Estados: creada / en proceso /
finalizada. Incorporación de repuestos.
Prioridad Alta
Restricciones Solo vehículos registrados pueden
tener órdenes de servicio activas.
Interacción humano-tecnológica Si
Interacción tecnológica- tecnológica Si
Estado de implementación: SI (Completado)
Detalles de implementación: Flujo completo funcional. Los mecánicos abren órdenes y el administrador gestiona sus estados globales (ABIERTA, PROCESO, ESPERA, TERMINADO, FACTURADO).

--------------------------------------------------------------------------------

Id del requisito RF04
Nombre Acceso al sistema por PIN
Componente Módulo de autenticación
Característica asociada Seguridad, control de acceso
Descripción Cada mecánico debe acceder utilizando
un PIN único asignado.
Características Control de actividades por usuario.
Registro de accesos.
Prioridad Alta
Restricciones El PIN solo puede ser asignado o
modificado por el administrador.
Interacción humano-tecnológica Sí
Interacción tecnológica-tecnológica Sí
Estado de implementación: SI (Completado)
Detalles de implementación: Autenticación por PIN implementada de manera segura. El administrador gestiona los PINs de acceso para toda la plantilla del personal.

--------------------------------------------------------------------------------

Id. Del requisito RF06
Nombre del requisito Gestión de inventario
Componente Un módulo de inventario
Característica asociada Control, actualización automática
Descripción del requisito Registrar entradas, salidas,
devoluciones y compras de repuestos.
Características Descuento automático al usar
repuestos. Alertas de stock bajo.
Prioridad Alta
Restricciones Sólo administradores pueden modificar
inventario directo.
Interacción humano-tecnológica Si
Interacción tecnológica- tecnológica Si
Estado de implementación: SI (Completado)
Detalles de implementación: Inventario funcional con búsqueda y categorización por secciones. Descuenta unidades del stock automáticamente al facturar o registrar una orden de servicio.

--------------------------------------------------------------------------------

Id. Del requisito RF08
Nombre del requisito Historial de reparaciones
Componente Módulo de historial
Característica asociada Registro permanente
Descripción del requisito Guardar historial técnico completo por
vehículo.
Características Fecha, mecánico, servicio, repuestos
usados.
Prioridad Alta
Restricciones Sólo personal autorizado consulta.
Interacción humano-tecnológica Si
Interacción tecnológica- tecnológica Si
Estado de implementación: PARCIAL
Detalles de implementación: El historial se almacena de forma íntegra en las tablas ordentrabajo y detalleorden, pudiendo ser auditado en cada factura, pero no se ha desarrollado una vista de búsqueda por número de placa en la interfaz de usuario.

--------------------------------------------------------------------------------

Id. Del requisito RF9
Nombre del requisito Registro de pagos y asociación con facturas
Componente Módulo de pagos
Característica asociada Seguridad, integración con facturación
Descripción del requisito El sistema debe permitir el registro de
pagos realizados por los clientes y
asociarlos a las facturas
correspondientes.
Características Debe soportar diferentes métodos de
pago (efectivo, tarjeta, transferencia).
El estado de la factura debe
actualizarse automáticamente al recibir
el pago.
Prioridad Alta
Restricciones Solo el personal autorizado puede
registrar pagos en el sistema.
Interacción humano-tecnológica Si
Interacción tecnológica- tecnológica Si
Estado de implementación: PARCIAL
Detalles de implementación: Permite la actualización inmediata de la orden a "FACTURADO" al recibir el pago, pero en el panel actual no se desglosa ni se almacena la opción del método de pago utilizado.

--------------------------------------------------------------------------------

Id. Del requisito RF11
Nombre del requisito Registro de compras de repuestos
Componente Módulo de inventario
Característica asociada control de entradas, actualización automática
Descripción del requisito El sistema debe permitir registrar
compras de repuestos a proveedores
para aumentar automáticamente el
stock.
Características Cada compra almacena proveedor,
fecha, repuestos adquiridos y
cantidades.
Prioridad Alta
Restricciones Solo administradores pueden registrar
compras.
Interacción humano-tecnológica Si
Interacción tecnológica- tecnológica Si
Estado de implementación: SI (Completado)
Detalles de implementación: Módulo de ingreso de pedidos completado, asociando proveedor, costo y cantidades compradas. Aumenta de manera automática el inventario del producto respectivo.

--------------------------------------------------------------------------------

Id. Del requisito RF13
Nombre del requisito Notificaciones de inventario bajo
Componente Módulo de inventario
Característica asociada control preventivo
Descripción del requisito Mostrar alertas automáticas cuando un
repuesto llegue a nivel mínimo.
Características Los límites de stock son configurables.
Prioridad Alta
Restricciones Solo el administrador define niveles
mínimos.
Interacción humano-tecnológica Si
Interacción tecnológica- tecnológica Si
Estado de implementación: PARCIAL
Detalles de implementación: Se visualizan alertas visuales automáticas en rojo en los paneles cuando el stock es menor a 5. Sin embargo, no se implementó la opción de parametrizar o configurar dicho valor límite por pantalla.
