DIAPOSITIVA 4: Arquitectura del Proyecto (Patrón MVC)
--------------------------------------------------------------------------------
[TÍTULO]
Arquitectura Limpia: Patrón MVC

[CONTENIDO VISUAL (Esquema conceptual)]
- VISTAS (JSP + CSS): Interfaz dinámica e independiente (Ej. login.jsp, gestionarMecanicos.jsp).
- CONTROLADORES (Servlets): Lógica intermedia y direccionamiento seguro (Ej. LoginController.java).
- MODELOS y DAOs (Java + SQL): Representación de datos y consultas seguras (Ej. Empleado.java, EmpleadoDAO.java).

[NOTAS DEL EXPOSITOR (Lo que debes decir)]
"Para garantizar la escalabilidad de la aplicación, implementamos el patrón de diseño MVC (Modelo-Vista-Controlador). Esto divide limpiamente el código: la interfaz gráfica (Vista) es independiente de la lógica de negocio (Controlador), la cual a su vez se comunica con la base de datos de manera segura mediante los objetos de acceso a datos (Modelos y DAOs). Así, si requerimos cambiar el diseño visual, no afectamos las consultas ni la base de datos."

DIAPOSITIVA 5: Demostración Técnica: Flujo de Login
--------------------------------------------------------------------------------
[TÍTULO]
Flujo de Datos en el Sistema (Caso: Login por PIN)

[CONTENIDO VISUAL (Diagrama de pasos rápidos)]
1. VISTA: Usuario digita su PIN en 'login.jsp'.
2. CONTROLADOR: 'LoginController' recibe la solicitud vía HTTP POST.
3. DAO: Llama a 'EmpleadoDAO.loginPorPin()' para buscar en MySQL.
4. MODELO: Si existe y está ACTIVO, se construye un objeto 'Empleado'.
5. SESIÓN: El controlador guarda al empleado en la sesión del servidor (HttpSession) y lo redirige a su Dashboard.

[NOTAS DEL EXPOSITOR (Lo que debes decir)]
"Queremos mostrarles técnicamente cómo fluyen los datos en MotorDesk tomando como ejemplo el inicio de sesión. Cuando un empleado digita su PIN, la petición viaja a un Servlet controlador. Este le pide al DAO que haga un query seguro en la base de datos. Si el PIN coincide y el empleado está en estado 'Activo', se crea un objeto en memoria y se abre una sesión segura de servidor, redirigiendo al usuario a su panel correspondiente según su rol: Administrador o Mecánico."

DIAPOSITIVA 6: Gestión de Personal (Módulo de Mecánicos)
--------------------------------------------------------------------------------
[TÍTULO]
Administración del Personal Técnico

[CONTENIDO VISUAL]
- Listados Dinámicos: Extracción mediante FK (id_rol_fk = 2).
- Seguridad en BD: Uso de Prepared Statements para evitar ataques de Inyección SQL.
- Integridad de Datos: Validación automática del tipo de variable (Ej. ID Empleado como Long para soportar cédulas largas).
- Creación rápida: Registro ágil con fecha automatizada desde el servidor de base de datos.

[NOTAS DEL EXPOSITOR (Lo que debes decir)]
"El sistema permite administrar la grilla de mecánicos de forma dinámica. Hacemos consultas seguras filtrando exclusivamente por el rol de mecánico. Un detalle técnico importante es que el ID de empleado está modelado como una variable de tipo 'Long' en Java. Esto es crucial porque nos permite registrar documentos de identidad largos (de 10 o más dígitos) sin que ocurran desbordamientos de memoria en el servidor."

DIAPOSITIVA 7: Diseño Front-End Premium y Moderno
--------------------------------------------------------------------------------
[TÍTULO]
Experiencia de Usuario (UX) de Alto Impacto

[CONTENIDO VISUAL]
- CSS Desacoplado: Filosofía BEM (Block Element Modifier) para un código limpio.
- Glassmorphism (Efecto Cristal): Uso de 'backdrop-filter: blur' para un estilo visual muy elegante.
- Animaciones Micro-interactivas: Tarjetas de error animadas (efecto de temblor en inputs inválidos).
- Anti-Caché en Estilos: Carga dinámica con versión (?v=1.x) para garantizar que los cambios se vean al instante.

[NOTAS DEL EXPOSITOR (Lo que debes decir)]
"Nos esforzamos por crear una interfaz moderna. Implementamos la técnica de Glassmorphism (emulación de cristal esmerilado con desenfoque de fondo), lo que le da un aspecto sofisticado y limpio. Además, evitamos las molestas alertas tradicionales del navegador; en su lugar, si hay un error en los campos de entrada, la propia tarjeta del formulario tiembla visualmente con colores vivos de advertencia. También agregamos un sistema anti-caché en la importación de hojas de estilo para asegurar que los navegadores web siempre rendericen la última versión del diseño."
