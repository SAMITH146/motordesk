================================================================================
GUÍA DE EXPOSICIÓN Y EXPLICACIÓN DE ARQUITECTURA - MOTORDESK
================================================================================

Esta guía técnica explica detalladamente el funcionamiento de cada Modelo, DAO y 
Controlador del monolito MotorDesk. Está diseñada para ayudarte a exponer y 
responder cualquier pregunta técnica del jurado sobre cómo fluyen los datos y 
cómo se estructuran los componentes del proyecto.

--------------------------------------------------------------------------------
1. PATRÓN DE DISEÑO Y ESTRUCTURA GENERAL (MVC)
--------------------------------------------------------------------------------
El sistema utiliza el patrón MVC (Modelo-Vista-Controlador) bajo tecnología Java 
Web estándar (Servlets, JSPs y base de datos relacional MySQL/MariaDB):
- MODELOS: Clases Java simples (POJOs) que representan las entidades del mundo 
  real (ej. Empleado, Orden de Trabajo) con atributos privados y getters/setters.
- DAOs (Data Access Objects): Clases que encapsulan todas las sentencias SQL. 
  Ningún controlador ni vista escribe código SQL directamente; toda la 
  interacción con la BD se delega a los DAOs.
- CONTROLADORES (Servlets): Reciben peticiones HTTP (GET y POST), interpretan 
  parámetros, invocan métodos de lógica en los DAOs y redirigen a las vistas 
  apropiadas inyectando variables en el contexto (Session o Request).
- VISTAS (JSPs): Contienen el diseño web en HTML5, CSS3 (con estilo premium 
  glassmorphism) y etiquetas JSTL/EL para pintar dinámicamente los datos.

--------------------------------------------------------------------------------
2. CAPA DE MODELOS (java/com/mycompany/motordesk/model)
--------------------------------------------------------------------------------
Representan la estructura de datos en Java y son el "molde" de los registros de 
la base de datos:

- Empleado.java: Representa a los usuarios del taller. Contiene atributos como 
  idEmpleado (cédula del empleado como String para mayor flexibilidad), nombre, 
  pin (contraseña numérica), idRol (para diferenciar si es Administrador o 
  Mecánico), idCargo, estadoEmpleado (ACTIVO/INACTIVO) y fechaIngreso.
- Rol.java: Modelo simple que almacena el rol del usuario (1 = Administrador, 
  2 = Mecánico).
- Cliente.java: Almacena los datos personales de los clientes/dueños de vehículos: 
  idCliente (llave autoincremental de la BD), nombre, documento (cédula de 
  identidad) y dirección.
- Vehiculo.java: Representa los datos técnicos de los vehículos: idVehiculo, 
  idClienteFk (vinculación de clave foránea al dueño), placa, marca, modelo y año.
- OrdenTrabajo.java: El corazón del negocio. Almacena la cabecera del servicio: 
  idOrden, idVehiculoFk (vínculo al carro), docEmpleFk (mecánico asignado), 
  fecha, estado (ABIERTA, PROCESO, ESPERA, TERMINADO, FACTURADO), total, 
  descripcion, placaVehiculo y los campos de suspensión temporal (motivoEspera 
  y tiempoEspera).
- DetalleOrden.java: Representa cada fila/ítem interno de una orden. Vincula 
  idOrdenFk con un repuesto (idProductoFk), la cantidad utilizada y el subtotal.
- Producto.java: Modelo de inventario. Sirve tanto para repuestos como insumos. 
  Contiene idProducto, nombre, categoria, stock, precio, estado, fechaRegistro, 
  tipoVehiculo y seccion física de almacenamiento.
- Proveedor.java: Datos de contacto de los proveedores del taller (idProveedor, 
  nombre, contacto, telefono, correo).
- CompraRepuesto.java: Cabecera contable del ingreso de mercancía hecha por el 
  administrador. Contiene idCompra, idProveedorFk, fechaCompra y total pagado.
- DetalleCompra.java: Los ítems y cantidades ingresadas en una compra de repuestos 
  específica.

3. CAPA DE ACCESO A DATOS (java/com/mycompany/motordesk/dao)
--------------------------------------------------------------------------------
Aquí se maneja la persistencia y conectividad mediante JDBC. Se destaca el uso de 
PreparedStatements para proteger el sistema contra ataques de Inyección SQL.

- Conexion.java: Configura los parámetros de acceso a MySQL (localhost, puerto 
  3306, base de datos 'motordesk', usuario 'root' y contraseña 'COMPUTER.777'). 
  Usa `DriverManager.getConnection()` para abrir el canal de datos físico.
- EmpleadoDAO.java:
  - loginPorPin(pin): Compara el PIN ingresado con la base de datos asegurando 
    que el usuario esté 'ACTIVO'. Retorna el objeto Empleado si coincide.
  - CRUD (insertar, listarMecanicos, actualizar, eliminar, toggleEstado).
- ClienteDAO.java:
  - insertar(cliente): Guarda un cliente nuevo y retorna el ID autoincremental 
    generado en la BD.
  - obtenerPorDocumento(cédula): Busca si el cliente ya existe para evitar 
    duplicados.
  - obtenerPorId(id): Utilizado en el módulo de facturación para traer los datos 
    completos del cliente a partir de su clave primaria.
- VehiculoDAO.java:
  - insertar(vehiculo): Guarda el vehículo y retorna su ID generado.
  - obtenerPorPlaca(placa): Busca si la placa ya está registrada en el sistema.
  - obtenerPorId(id): Trae la información del carro asociada a la factura.
- OrdenDAO.java:
  - insertarOrden(orden, detalles): Este es el método más complejo y seguro. Usa 
    una TRANSACCIÓN SQL (`con.setAutoCommit(false)`). Primero calcula los costos 
    de los repuestos, valida que haya stock suficiente (lanzando una excepción 
    si no hay existencias), guarda la orden, inserta los detalles de forma masiva 
    (Batch) y descuenta el stock de los productos. Si algo falla, hace un 
    `rollback` para evitar datos corruptos.
  - actualizarOrden(): Permite al mecánico agregar o quitar repuestos del 
    servicio, restaurando el stock anterior e insertando los nuevos cambios.
  - actualizarEstado(): Cambia el estado del trabajo (ej: ABIERTA -> TERMINADO).
  - obtenerPorId() y mapearOrden(): Transforma las filas de SQL en objetos Java.
- ProductoDAO.java: Gestiona los productos, repuestos, precios y niveles de stock.
- ProveedorDAO.java: Administra los proveedores.
- CompraRepuestoDAO.java: Registra las facturas de reabastecimiento en la BD y 
  aumenta automáticamente las cantidades en el inventario.
- PanelMecanicoDAO.java: Ejecuta consultas rápidas de agregación (COUNT) para 
  mostrar estadísticas al mecánico (ej: cuántas órdenes tiene abiertas hoy).
- AdminDAO.java: Genera estadísticas de control para el dashboard administrativo.

4. CAPA CONTROLADORA (java/com/mycompany/motordesk/controller)
--------------------------------------------------------------------------------
Interceptan el tráfico de la web, coordinan a los DAOs y deciden qué vista JSP 
mostrar.

- LoginController.java: Captura el PIN enviado desde el formulario de login. JSP. 
  Llama al `EmpleadoDAO.loginPorPin()`. Si es válido, inyecta al empleado en la 
  sesión de servidor (`HttpSession`) y redirige según su Rol: rol 1 al dashboard 
  del administrador y rol 2 al panel del mecánico.
- LogoutController.java: Invalida la sesión actual en el servidor web y expulsa 
  al usuario de vuelta al login.
- PanelMecanicoController.java: Alimenta el panel del mecánico trayendo las 
  órdenes asignadas al usuario logueado, alertas de stock bajo y catálogo de 
  productos disponibles para la orden de trabajo.
- OrdenController.java:
  - doGet() - action=listAll: Envía todas las órdenes del sistema al panel de 
    control del Administrador.
  - doGet() - action=verFactura: El módulo nuevo del Paso 4. Recibe la orden por ID, 
    busca su vehículo y cliente correspondientes, carga la lista de repuestos, 
    inyecta todo en el request y despacha hacia `/admin/factura.jsp`.
  - doPost() - action=insert: Ejecutado cuando el mecánico crea una orden. De forma 
    inteligente, primero procesa al Cliente (lo crea si no existe o lo actualiza 
    si cambió de datos), luego al Vehículo (lo crea o actualiza), asocia la 
    orden a este vehículo, asigna el mecánico actual y delega a `OrdenDAO.insertarOrden()`.
  - doPost() - action=updateStatus: Usado en la factura o la tabla general para 
    recibir pagos y facturar, marcando la orden como `FACTURADO`.
- ClienteController.java: Permite al administrador listar, buscar y editar los 
  datos del cliente desde la nueva sección del panel del admin.
- MecanicoController.java: Administra los mecánicos del taller.
- ProductoController.java: Controla el inventario de repuestos y productos.
- CompraRepuestoController.java: Gestiona los flujos de reabastecimiento de repuestos.
- AdminDashboardController.java: Rellena el dashboard general del taller con el 
  resumen diario para el administrador.

--------------------------------------------------------------------------------
5. DETALLES TÉCNICOS DESTACADOS PARA EXPLICAR AL JURADO
--------------------------------------------------------------------------------
- Transaccionalidad Segura: Explica cómo `insertarOrden()` en `OrdenDAO` es 
  transaccional. Si hay 5 repuestos agregados y el quinto no tiene stock, la 
  operación completa se cancela mediante `rollback()`. Esto evita que se creen 
  órdenes "huérfanas" o sin stock real.
- Integridad Referencial: Cada orden está conectada físicamente en la BD a un 
  Vehículo, y el Vehículo a su vez a un Cliente. Este flujo `Cliente -> Vehículo 
  -> Orden` mantiene la consistencia relacional de la BD.
- Diseño de Impresión CSS: La factura (`factura.jsp`) cuenta con estilos de 
  impresión mediante `@media print`. Al presionar el botón "Imprimir", el CSS 
  oculta el navbar superior, el fondo degradado y los botones de acción para 
  generar una hoja física limpia en blanco y negro, lista para entregar al cliente.
